# تشغيل التحديث الآلي على Netlify — مشروع وقاية

## مهم قبل البدء
Netlify لا يستطيع تحديث نسخة ZIP التي رفعتها يدويًا تلقائيًا. الحل في هذه النسخة هو ربط Netlify بمستودع GitHub: مهمة GitHub Actions تجلب قوائم التهديدات كل 15 دقيقة تقريبًا، تحفظها في `data/threats.json`، ثم يلتقط Netlify التغييرات وينشرها.

## الإعداد لأول مرة
1. فك ZIP وارفع **جميع الملفات** في جذر مستودع GitHub، بما فيها المجلد المخفي `.github/workflows/`.
2. في GitHub افتح **Settings → Actions → General → Workflow permissions** واختر **Read and write permissions** إذا سمحت سياسة المستودع بذلك. وقد تتطلب الفروع المحمية إعداد صلاحية مناسبة.
3. في Netlify افتح **Add new project → Import an existing project → GitHub**، واختر المستودع. إذا كان الموقع قائمًا أصلًا في Netlify، استخدم إعدادات الموقع لربطه بالمستودع بدل إنشاء موقع جديد.
4. إعدادات النشر في Netlify: **Build command** اتركه فارغًا، و**Publish directory** اكتب `.`. ملف `netlify.toml` مضاف وجاهز لهذا الإعداد.
5. في GitHub افتح **Actions → Refresh phishing data → Run workflow** لتوليد أول قائمة.
6. راجع نجاح مهمة GitHub Actions، ووجود محتوى فعلي في `data/threats.json`، ثم نجاح نشر Netlify.
7. افتح `https://YOUR-SITE.netlify.app/data/threats.json` واستبدل YOUR-SITE باسم موقعك. يجب أن ترى `updatedAt` غير فارغ و`lists` تحتوي بيانات فعلية.

## التحديثات
- GitHub Actions يطلب تحديثًا كل 15 دقيقة. قد تتأخر الجدولة، ولا يوجد ضمان زمني صارم.
- بعد نجاح التحديث، ينشئ GitHub Actions commit لملف البيانات، ويبدأ Netlify نشرًا جديدًا تلقائيًا عند ربطه بالمستودع.
- الواجهة تتحقق من البيانات الجديدة أثناء الاستخدام؛ الزوار لا يحتاجون لإبقاء صفحاتهم مفتوحة كي تتم مزامنة المصدر.
- بعد التحديث الأول يلزم بقاء GitHub Actions والنشر الآلي على Netlify مفعلين. لم يتم تفعيلهما داخل حسابك بواسطة هذا الملف.

## مشاكل شائعة
- إذا بقي `at: 0` فالبيانات لم تُجلب بعد؛ شغّل workflow يدويًا وراجع سجلاته.
- إذا ظهر خطأ 403 عند `git push` فراجع صلاحيات Workflow وإعدادات حماية الفرع.
- إذا تحدّث GitHub ولم يتحدّث الموقع، راجع **Netlify → Deploys** وتأكد أن الموقع مربوط بالمستودع نفسه والفرع الافتراضي.
- إذا عادت المصادر بخطأ، فلن تستبدل المهمة البيانات ببيانات فارغة إذا فشل جميع المصادر.
